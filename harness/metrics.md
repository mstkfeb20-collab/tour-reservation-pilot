# 指標

二つに分ける。混ぜると、案件の出来と型の出来の区別がつかなくなる。

- **案件の品質指標**: この案件の成果物の品質。工程の出口で案件リーダーが判定し、従来の品質報告に載せる。
- **月次の指標（型の指標）**: ハーネス（tazuna）が効いているか。標準化チームに共有する。案件の優劣を付けるためではない。

## 案件の品質指標

何を見て、何を測り、何を判断するか（考え方・指標の定義・分母の換算・出口基準）は [`quality.md`](quality.md)。ここには記録だけを置く。基準値は品質計画で決め、パイロットで作り直す。

### 基準値（品質計画から写す）

| 項目 | 値 | メモ |
| --- | --- | --- |
| 設計: 見積 KLOC と推定枚数 | | 推定枚数 = 見積 KLOC × 過去の「枚数 / KLOC」（quality.md の「指標の規模」） |
| 設計: 許容件数（推定枚数 × 従来の基準値） | | |
| 設計: 決定の行数あたりの指摘密度の範囲 | | 許容件数 ÷ 決定の行数。単位（件/100行 など）も書く |
| コード: 類似案件との KLOC の比率（AI ÷ 人） | | 類似案件名と、比べた単位（画面数など） |
| 単体: 分岐カバレッジの下限 | | `pom.xml` の `tazuna.coverage.branch.min` |
| 単体: ミューテーションスコアの下限 | | `pom.xml` の `tazuna.mutation.min` |
| 結合: 試験密度・バグ密度の範囲 | | KLOC は上の比率で換算 |

## 月次の指標（型の指標）

月次の見直しで案件リーダーが更新し、標準化チームに共有する。

| 指標 | 見るもの | 期待する動き |
| --- | --- | --- |
| rule-log の件数（防ぐ層ごと） | 仕組み化が進んでいるか | 「文章」の割合が下がる |
| 追加した Lint ルール数 | ミスがルールに変わっているか | 初期に増え、やがて落ち着く |
| PR数とリバート率 | エージェントの成果を信頼できるか | PR数が増えてもリバート率が上がらない |
| 同じレビュー指摘の再発数 | 改善が効いているか | 減る |
