## REQ-22001 振込データ取込

- 背景: ID 設計 S-22-001 処理設計書：振込データ取込 で決めた完了条件。
- 完了条件:
  - 受信フォルダに振込入金通知ファイルが1つだけあること（S-22-001/D-01004/1・事前条件）
  - 取り込んだ明細は、すべて 消込済・不一致・返金対象・要確認 のどれかになっている（S-22-001/D-01005/1・事後条件）
  - 消し込めなかった明細は、すべて不一致リストか返金対象リストに出ている（S-22-001/D-01005/2・事後条件）
  - 返金対象の金額は、その明細の振込額の全額（S-22-001/D-04001/1・計算式）
  - 振込依頼人名の先頭13桁が R + 数字12桁 なら、予約番号とみなす（S-22-001/D-04003/1・判定条件・分岐）
  - 振込依頼人名に予約番号がなければ、氏名と金額が一致する未振込の予約が1件だけあっても自動では消し込まない（S-22-001/D-04003/2・判定条件・分岐）
  - 予約番号の予約が見つからなければ「不一致（予約なし）」（S-22-001/D-04003/3・判定条件・分岐）
  - 振込額が合計金額と一致したら、予約を振込済にする（S-22-001/D-04003/4・判定条件・分岐）
  - 振込額が合計金額より少なければ「不一致（不足）」とし、振込済にしない（S-22-001/D-04003/5・判定条件・分岐）
  - 振込額が合計金額より多ければ「不一致（超過）」とし、振込済にしない（S-22-001/D-04003/6・判定条件・分岐）
  - 予約がすでに振込済なら「返金対象（二重振込）」（S-22-001/D-04003/7・判定条件・分岐）
  - 予約が取消済なら「返金対象（取消後の入金）」（S-22-001/D-04003/8・判定条件・分岐）
  - 取消区分が '1'（組戻し）の明細は消込に使わず、「要確認（組戻し）」として予約担当に回す（S-22-001/D-04003/9・判定条件・分岐）
  - 銀行休業日の翌朝はファイルが来ないので、J110 を起動しない（S-22-001/D-04006/1・業務カレンダー）
  - EDI情報に予約番号があれば、振込依頼人名より優先して使う（S-22-001/D-04007/1・優先順位・競合の解決）
  - 同じ予約への明細が同じファイルに2件あれば、照会番号の小さい方を消込に使い、もう1件は返金対象にする（S-22-001/D-04007/2・優先順位・競合の解決）
  - 明細の判定は D-04003 の [9] → [3] → [8] → [7] → [4] → [5] → [6] の順に当てはめ、最初に当てはまったもので決める（S-22-001/D-04007/3・優先順位・競合の解決）
  - 勘定日が振込期限を過ぎていても消し込む。ただし期限後入金の印を付ける（S-22-001/D-04008/1・期限・締め・タイミング）
  - 1明細の、予約の更新と取込結果の登録は、両方成功するか両方失敗する（S-22-001/D-06004/1・原子性）
  - 振込済になった予約は、手配会社に入金済を伝えるため、手配連携待ちに積む（S-22-001/D-06005/1・システム間の整合・補償処理）
  - 形式検査でエラーがあれば、何も更新せずに終了コード 8 で終わる（S-22-001/D-09007/1・エラー時のデータ状態）
  - S3 の途中で異常終了したら、コミット済みの明細はそのまま残し、再実行で残りを処理する（S-22-001/D-09007/2・エラー時のデータ状態）
  - 消し込んだ予約ごとに、操作者 'J110'・照会番号・金額 を操作ログに残す（S-22-001/D-10006/1・操作ログ・監査証跡）

### 実装するときの条件（S-22-001）

- 振込期限を過ぎても未振込の予約は、予約担当が確認してから取り消す。J110 は自動で取り消さない（S-22-001/D-04009/1・例外的な業務判断）
- 振込取込の issue では、この機能の要件（docs/requirements/S-22-001_振込データ取込.md）と、IF定義書（S-24-001 IF-11振込入金通知ファイル）のレコードの形を読む（S-22-001/D-18008/1・参照すべき文書の指定）

### 型・Lint で守る決まり（S-22-001・業務の承認済み）

- J110 が行う遷移は 未振込(0) → 振込済(1) だけで、他の遷移はしない（S-22-001/D-04004/1・状態と状態遷移）
- 1つの予約に、消込に使った明細は1件まで（S-22-001/D-04005/1・不変条件）
- 手配連携待ちには 予約番号・入金日 を積む（S-22-001/D-07008/1・項目の対応表）

## REQ-23001 J110振込取込（ジョブ設計書）

- 背景: ID 設計 S-23-001 ジョブ設計書：J110振込取込 で決めた完了条件。
- 完了条件:
  - J110 は途中で止まっても最初から再実行してよい。消込済みの明細は二重に消し込まない（S-23-001/D-08005/1・再実行性）
  - 再実行のときは、取込結果テーブルに同じ勘定日・照会番号がある明細を読み飛ばす（S-23-001/D-08005/2・再実行性）
  - J110 が終了コード 8 で終わったら、J120・J310 は実行しない（S-23-001/D-08006/1・異常終了時の後続制御）
  - 消込の相手になるのは TRANSFER = '0'（未振込）の予約（S-23-001/D-08010/1・対象データの抽出条件）
  - トレーラーの合計件数・合計金額が、データレコードの件数・金額の合計と一致すること（S-23-001/D-08011/1・件数・金額の突合）
  - 明細件数 = 消込件数 + 不一致件数 + 返金対象件数 + 要確認件数（S-23-001/D-08011/2・件数・金額の突合）
  - 明細の合計金額 = 消込金額 + 不一致金額 + 返金対象金額 + 要確認金額（S-23-001/D-08011/3・件数・金額の突合）
  - J110 の処理日は業務日付を使い、システム日付は使わない（S-23-001/D-08014/1・業務日付とシステム日付）

### 実装するときの条件（S-23-001）

- リストは90日後に削除する（S-23-001/D-08008/1・入出力ファイルの退避・世代）
- 取り込んだファイルは /data/archive/bank に日付を付けて移し、13か月分保持する（S-23-001/D-08008/2・入出力ファイルの退避・世代）
- J110 が異常終了したら、運用担当は原因を確かめ、入力ファイルはそのままで再実行する（S-23-001/D-08012/1・オペレーター対応手順）
- 形式エラーのときは銀行に再送を頼み、届いたファイルで再実行する（S-23-001/D-08012/2・オペレーター対応手順）
- 不一致・返金対象・要確認が1件でもあれば、予約担当にメールで件数を知らせる（S-23-001/D-09006/1・障害通知）
- J110 が異常終了したら、運用担当にすぐ知らせる（S-23-001/D-09006/2・障害通知）
- J110 の開始・終了と終了コードを監視し、6:30 を過ぎても終わらなければ知らせる（S-23-001/D-16001/1・運用監視項目）

### 型・Lint で守る決まり（S-23-001・業務の承認済み）

- J110 は振込入金通知ファイルの到着で起動する（S-23-001/D-08002/1・起動条件）
- 6:00 までにファイルが届かなければ起動せず、運用担当に知らせる（S-23-001/D-08002/2・起動条件）
- J120 残席突合は、J110 が終了コード 0 または 4 で終わった後に動く（S-23-001/D-08003/1・先行・後続関係）
- J110 は平常10分以内、繁忙期でも30分以内に終える（S-23-001/D-08007/1・処理時間・バッチウィンドウ）
- 夜間ジョブネット全体は、7:00 の窓口開店までに終える（S-23-001/D-08007/2・処理時間・バッチウィンドウ）
- 3千件のファイルを30分以内に処理できることを、本番相当の環境で測る（S-23-001/D-08007/3・処理時間・バッチウィンドウ）

## REQ-24001 IF-11振込入金通知ファイル（IF定義書）

## テスト仕様：振込データ取込（S-26-001）

テスト担当は、この観点からテストを作り、各テストに確かめる要件の ID（@Tag）を付ける。

- 予約番号が 振込依頼人名にある・EDI情報にある・両方にあって食い違う・どちらにもない の4通りを確かめる（S-26-001/D-15001/1・テスト観点・ケース）
- 振込済・取消済の予約への入金が、返金対象になることを確かめる（S-26-001/D-15001/2・テスト観点・ケース）
- 同じ予約への明細が同じファイルに2件あるとき、照会番号の小さい方だけが消し込まれる（S-26-001/D-15001/3・テスト観点・ケース）
- 組戻しの明細が消込に使われず、要確認になる（S-26-001/D-15001/4・テスト観点・ケース）
- トレーラーの合計件数・合計金額がずれたファイルでは、1件も消し込まれない（S-26-001/D-15001/5・テスト観点・ケース）
- S3 の途中で止めて再実行しても、二重に消し込まれない（S-26-001/D-15001/6・テスト観点・ケース）
- 画面からの取消と消込が同時に起きたとき、その明細が要確認になる（S-26-001/D-15001/7・テスト観点・ケース）
- 明細が0件のファイルでも正常終了する（S-26-001/D-15001/8・テスト観点・ケース）
- 振込額が合計金額と 一致・1円不足・1円超過 の3通りを確かめる（S-26-001/D-15003/1・境界値・同値クラス）
- 勘定日が振込期限の当日なら期限後入金の印が付かず、翌日なら付く（S-26-001/D-15003/2・境界値・同値クラス）
- 取引銀行のテスト環境から実際にファイルを受信し、形式検査を通ることを確かめる（S-26-001/D-15008/1・結合・総合テストの観点）

### 実装するときの条件（S-26-001）

- 振込入金通知ファイルはテストごとに生成ツールで作り、本物の明細は使わない（S-26-001/D-15002/1・テストデータの準備）
- 消込を変えたら、予約照会の振込状況表示と予約取消の取消料も回帰テストする（S-26-001/D-15007/1・回帰テストの範囲）
