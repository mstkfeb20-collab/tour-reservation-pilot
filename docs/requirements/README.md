# 要件（完了条件の正本）

要件と完了条件はこのフォルダに書く。管理者は社員（CODEOWNERS: business-team）。エージェントは編集できない（hooks で保護）。

## 進め方

1. ID 設計書（`docs/design/`）を書き、PR でレビューする。
2. 機能の資料がそろったら `python3 scripts/design/transcribe.py` で転記し、要件とテスト仕様を PR で決める（社員が承認）。
3. 実装とテストを書く（エージェント・協力会社）。
4. Lint と CI を通してマージする。PR の「対象要件」に挙げた要件には、テストがなければならない。

転記したファイル（`S-22-005_振込データ取込.md` など）は、目印で囲んだ部分を手で直さない。直したいときは設計書を直して転記し直す。目印の外には手で書いてよい。

## 書き方（手で書く場合）

- 1ファイル1機能領域（例: `reservation.md`）。
- 要件ごとに `## REQ-001 タイトル` の見出しを付ける。番号は案件内で一意にし、使い回さない。
- 見出しの下に「背景」「完了条件」を書く。完了条件は、テストで確かめられる形（入力と期待結果）で書く。
- 要件を書いたファイルには `## テスト仕様` の節を設け、何で確かめるかを書く。

## テストとの対応（Lint COMMON-003）

- テストクラスに `@Tag("REQ-001")` を付けて要件と紐づける。
- 要件を決める段階（②）では、完了条件のない要件と、テスト仕様のない要件ファイルをエラーにする。
- テストのまだない要件はエラーにしない。進捗（`python3 scripts/design/id_design.py progress`）で「未実装」と出る。
- 実装の PR では、本文の `対象要件: REQ-xxx` に挙げた要件にテストがなければエラーにする。PR の本文に「対象要件:」の行がないこともエラー（要件を実装しない PR は `対象要件: なし`）。CI は PR の今の本文を読み、本文を直すとやり直される。PR のレポート（CI のコメント）は、テストに付けたテスト仕様の行ID（`@Tag("S-26-xxx/D-xxxxx/n")`）と、PR の本文の「未対応: 行ID（理由）」の行を数える。エージェント（Copilot）が作った PR の本文は、人が編集しない（人が一度編集すると、エージェントが本文を書き換えなくなることがある）。直してほしいことはコメントで頼み、CI のやり直しは Actions の「Re-run jobs」を使う。
- テストが参照する要件IDが定義されていなければ、いつでもエラーにする。
- 要件を廃止するときは、見出しを削除し、対応するテストも削除する（テストの削除は人が行う）。
