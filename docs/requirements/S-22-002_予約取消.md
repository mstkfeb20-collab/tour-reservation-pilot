## REQ-22002 予約取消

- 背景: ID 設計 S-22-002 処理設計書：予約取消 で決めた完了条件。
- 完了条件:
  - 予約があり、振込状況が 0 未振込 か 1 振込済 であること（S-22-002/D-01004/1・事前条件）
  - 出発日の前日までであること（S-22-002/D-01004/2・事前条件）
  - 予約の振込状況が 9 取消になり、取消日と取消理由が記録されている（S-22-002/D-01005/1・事後条件）
  - ツアーの残席が、予約の人数（大人＋子供）だけ戻っている（S-22-002/D-01005/2・事後条件）
  - 入金額が取消料より多いときは、差額が返金待ち（REFUND）に1件登録されている（S-22-002/D-01005/4・事後条件）
  - 入金額が取消料より少ないときは、差額が請求待ち（CLAIM）に1件登録されている。入金がなければ取消料の全額（S-22-002/D-01005/5・事後条件）
  - 入金額と取消料が同じとき（取消料0円で入金もないときを含む）は、返金待ちにも請求待ちにも登録しない（S-22-002/D-01005/6・事後条件）
  - 未振込の予約の、不一致（不足・超過）の明細は、振込取込結果が「取消で精算済」になっている（返金・請求に入金を含めたため、不一致リストからの手作業と二重にしない）（S-22-002/D-01005/7・事後条件）
  - 同じ予約を2つの画面から同時に取り消したら、後の方は「この予約はすでに取り消されています」になる（S-22-002/D-01012/1・同時実行時の振る舞い）
  - 振込状況が 9 取消の予約は取り消せない（S-22-002/D-03004/1・業務的な妥当性チェック）
  - 取消料 = 合計金額 × 取消料率（S-22-002/D-04001/1・計算式）
  - 入金額 = 振込済の予約は RESERVE.PAID_AMOUNT。未振込の予約は、その予約番号の振込取込結果のうち、不一致（不足 '22'・超過 '23'）の明細の振込額の合計。どちらもなければ0円（S-22-002/D-04001/3・計算式）
  - 返金額 = 入金額 − 取消料。0円を下回らない（S-22-002/D-04001/4・計算式）
  - 請求額 = 取消料 − 入金額。0円を下回らない（S-22-002/D-04001/5・計算式）
  - 取消料は1円未満を切り捨てる（S-22-002/D-04002/1・端数処理）
  - 取消料率は出発日までの日数で決まる。21日前まで0%、20〜8日前20%、7〜2日前30%、前日40%（S-22-002/D-04003/1・判定条件・分岐）
  - 取消料は旅行代金に対する費用なので、入金の有無にかかわらず、取消料率に従って請求する（未振込の予約も同じ）（S-22-002/D-04003/3・判定条件・分岐）
  - 入金があれば取消料との差額を精算する。入金額が取消料より多ければ差額を返金し、少なければ差額を別途請求する。入金がなければ取消料の全額を請求する（S-22-002/D-04003/4・判定条件・分岐）
  - J110 の消込と同時に取り消したときは、取消を優先する。取消の側は版番号の競合を検知したら予約を読み直し、振込状況を見直して1回だけやり直す（J110 側の明細は要確認 41 になる。S-22-001/D-06003/1）（S-22-002/D-04007/1・優先順位・競合の解決）
  - 日数は、取消の操作をした日（システム日付）から出発日までで数える（S-22-002/D-04008/1・期限・締め・タイミング）
  - 返金番号は 'F' + 取消日の年月日8桁 + その日の連番4桁（S-22-002/D-04012/1・採番ルール）
  - 請求番号は 'C' + 取消日の年月日8桁 + その日の連番4桁（S-22-002/D-04012/2・採番ルール）
  - 取消の操作ログに、予約番号・操作した人（会員番号または社員番号）・取消料・入金額・返金額・請求額を残す（S-22-002/D-10006/2・操作ログ・監査証跡）
  - お客様と窓口担当が使える（S-22-002/D-11002/1・機能の認可）
  - お客様は自分の会員番号の予約だけ、窓口担当はすべての予約を取り消せる（S-22-002/D-11003/1・データの認可）

### 実装するときの条件（S-22-002）

- 期限後入金の印（LATE_PAYMENT_FLAG = '1'）がある振込済の予約も、ほかの振込済と同じに扱う（S-22-002/D-04009/1・例外的な業務判断）
- RESERVE → TOURINFO → TRANSFER_IMPORT → REFUND・CLAIM の順に更新する（J110 と同じく RESERVE を先にする）（S-22-002/D-06007/2・ロックの順序）
- 予約取消の issue では、この機能の要件（docs/requirements/S-22-002_予約取消.md）と、既存の取消の要件（docs/requirements/reservation.md の REQ-002・REQ-003）を読む（S-22-002/D-18008/1・参照すべき文書の指定）

### 型・Lint で守る決まり（S-22-002・業務の承認済み）

- 振込状況は 0 未振込 → 9 取消、1 振込済 → 9 取消 と移る。9 取消から戻すことはない（S-22-002/D-04004/1・状態と状態遷移）

## テスト仕様：予約取消（S-26-002）

テスト担当は、この観点からテストを作り、各テストに確かめる要件の ID（@Tag）を付ける。

- 振込済の予約を取り消すと、返金待ちが1件、返金額 = 入金額 − 取消料 で登録される（S-26-002/D-15001/2・テスト観点・ケース）
- 取消済の予約をもう一度取り消すとエラーになり、残席も返金待ちも変わらない（S-26-002/D-15001/3・テスト観点・ケース）
- 取消の途中で予約が振込済に更新されたら、読み直して振込済として取り消し、返金待ちを登録する（S-26-002/D-15001/4・テスト観点・ケース）
- お客様は他の会員の予約を取り消せない。窓口担当は取り消せる（S-26-002/D-15001/5・テスト観点・ケース）
- 入金のない未振込の予約を取り消すと、取消料の全額で請求待ちが1件登録され、返金待ちは登録されない。残席が戻る（S-26-002/D-15001/6・テスト観点・ケース）
- 不一致（不足）の明細がある未振込の予約を取り消すと、入金額が取消料より少なければ差額で請求待ちが、多ければ差額で返金待ちが1件登録され、その明細の振込取込結果が '50' 取消で精算済になる（S-26-002/D-15001/7・テスト観点・ケース）
- 不一致（超過）の明細がある未振込の予約を取り消すと、入金額（超過分を含む振込額）から取消料を引いた差額で返金待ちが1件登録される（S-26-002/D-15001/8・テスト観点・ケース）
- 振込済の予約で、取消料が入金額を上回ることはない（合計金額 × 40% が上限のため）。振込済の予約の取消では請求待ちを登録しない（S-26-002/D-15001/9・テスト観点・ケース）
- 取消の画面と操作ログに、取消料・入金額・返金額・請求額が出る（S-26-002/D-15001/10・テスト観点・ケース）
- 出発日まで 21・20・8・7・2・1・0日 の取消料率（0日は取り消せない）（S-26-002/D-15003/1・境界値・同値クラス）
- 取消料の1円未満の切り捨て（S-26-002/D-15003/2・境界値・同値クラス）
- 入金額と取消料の関係: 入金額 = 取消料 − 1円（請求1円）、= 取消料（返金も請求もしない）、= 取消料 + 1円（返金1円）（S-26-002/D-15003/3・境界値・同値クラス）
- 取消料0円（21日前まで）で入金のない未振込の予約: 返金待ちにも請求待ちにも登録しない（S-26-002/D-15003/4・境界値・同値クラス）
- J110 が不足の明細を取り込むのと同じときに、その予約を取り消しても、入金が返金・請求のどちらにも含まれないことや、二重に含まれることがない（実際の DB のロックが要るため結合で確かめる。#12）（S-26-002/D-15008/1・結合・総合テストの観点）

### 実装するときの条件（S-26-002）

- 予約取消を変えたら、J110 の要確認（版番号の競合）と取消後の入金（32）のテストも回帰テストする（S-26-002/D-15007/1・回帰テストの範囲）
