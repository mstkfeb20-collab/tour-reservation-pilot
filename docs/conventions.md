# 命名・作法

管理者は案件リーダー。ここに書いたルールのうち、機械的に判定できるものは順次 `scripts/lint/domain/` に移す。

> 以下は見本です。案件の技術スタックに合わせて書き換えてください。

## 命名
- クラス名・メソッド名は `docs/domain/glossary.md` の「コード上の名前」に合わせる。
- テストクラスは `<対象クラス>Test`、`@DisplayName` は日本語で業務の言葉を使う。

## 作法
- 値は不変（final フィールド、セッターなし）を基本にする。
- 状態の変更は意味のある名前のメソッドで行う（`setStatus` ではなく `cancel()`）。
- 例外メッセージは日本語で、何が起きたか・なぜできないかを書く。
- コメントで「なぜこう書いたか」を説明したくなったら、まず名前と構造で表せないか考える。回避策をコメント付きで残すと、エージェントがそれを手本として広げる。

## 上書きのルール
- 組織の標準 → 案件の標準 → タスク固有 の順に優先する。
- 業務の不変条件とセキュリティは上書きできない。
- 命名・作法は、理由をこのファイルに書けば上書きできる。
