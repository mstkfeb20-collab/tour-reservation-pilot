## 型・API・DB 制約で書けなくする

- [ ] 入力は予約番号と取消理由（必須、100文字まで）（S-22-002/D-01006/1・入出力の一覧）
- [ ] 出力は取消料・入金額・返金額・請求額（画面に表示する）（S-22-002/D-01006/3・入出力の一覧）
- [ ] 振込状況は 0 未振込 → 9 取消、1 振込済 → 9 取消 と移る。9 取消から戻すことはない（S-22-002/D-04004/1・状態と状態遷移）

## Lint を足す

- [ ] 取消料と返金額の計算は domain の CancellationPolicy、取消の手順は application の ReservationService に置く（S-22-002/D-01007/1・モジュール構成・クラス分割）
- [ ] 返金待ちの登録は domain に RefundRepository を置き、infrastructure で実装する（S-22-002/D-01007/2・モジュール構成・クラス分割）
- [ ] 請求待ちの登録は domain に ClaimRepository を置き、infrastructure で実装する。入金額を求めるため、振込取込結果を読む TransferImportRepository を domain に置く（S-22-002/D-01007/3・モジュール構成・クラス分割）
- [ ] 予約がない、またはお客様が他の会員の予約を指定した →「この予約は取り消せません」（S-22-002/D-03011/1・エラーとメッセージの対応）
- [ ] 出発日の当日以降 →「取消期限を過ぎています」（S-22-002/D-03011/2・エラーとメッセージの対応）
- [ ] すでに取り消されている →「この予約はすでに取り消されています」（S-22-002/D-03011/3・エラーとメッセージの対応）
- [ ] RESERVE を読み、更新する（TRANSFER・CANCEL_DATE・CANCEL_REASON・VERSION）（S-22-002/D-05006/1・CRUD）
- [ ] TOURINFO を読み、残席を更新する（S-22-002/D-05006/2・CRUD）
- [ ] REFUND に登録する（S-22-002/D-05006/3・CRUD）
- [ ] TRANSFER_IMPORT を読み、精算した不一致の明細の RESULT を '50' 取消で精算済 に更新する（S-22-002/D-05006/4・CRUD）
- [ ] CLAIM に登録する（S-22-002/D-05006/5・CRUD）
- [ ] 予約の更新・残席の戻し・不一致の明細の更新・返金待ちか請求待ちの登録・操作ログは、1つのトランザクションで行う（S-22-002/D-06001/2・トランザクション境界）

## テストを書く（業務承認の要らない振る舞い）

- [ ] 予約取消画面の「取り消す」ボタン（S-22-002/D-01003/1・処理の起動契機）
- [ ] 予約を読む → 取り消せるか判定する → 入金額を求める → 取消料・返金額・請求額を計算する → 予約を取消にする → 残席を戻す → 不一致の明細を取消で精算済にする → 返金待ちか請求待ちを登録する → 操作ログを残す（S-22-002/D-01010/2・処理シーケンス）
- [ ] RESERVE は版番号で更新する。競合したときの扱いは D-04007 の [1]（S-22-002/D-06003/1・排他制御の方式）

## 承認されているか確かめる

- [ ] 期限後入金の印（LATE_PAYMENT_FLAG = '1'）がある振込済の予約も、ほかの振込済と同じに扱う（S-22-002/D-04009/1・例外的な業務判断）
