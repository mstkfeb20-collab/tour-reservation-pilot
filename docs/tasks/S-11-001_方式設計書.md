## 型・API・DB 制約で書けなくする

- [ ] DB の文字コードは AL32UTF8 とする（S-11-001-006・文字コード・照合順序）
- [ ] 分離レベルは READ COMMITTED とする（S-11-001-010・分離レベル）

## Lint を足す

- [ ] 画面制御（Controller）・ユースケース（Service）・ドメイン（業務ルール）にクラスを分ける（S-11-001-001・モジュール構成・クラス分割）
- [ ] 取消料率・残席の確保などの業務ルールは domain 層に置き、画面制御やSQLに書かない（S-11-001-002・レイヤー配置）
- [ ] 日数の計算は共通部品 BusinessCalendar を使い、各機能で日付を直接引き算しない（S-11-001-003・共通部品の利用）
- [ ] 全テーブルに 作成者・作成日時・更新者・更新日時 を持たせる（S-11-001-005・監査項目）
- [ ] SQL は文字列連結で組み立てない（S-11-001-007・SQLの書き方規約）
- [ ] トランザクションはユースケース（Service）のメソッド単位で張る（S-11-001-008・トランザクション境界）
- [ ] 業務エラーは BusinessException、想定外の障害は SystemException を継承する（S-11-001-012・例外の分類）
- [ ] 例外を catch してよいのは画面制御層と共通ハンドラだけ（S-11-001-013・例外を捕捉する場所）
- [ ] 空の catch ブロックは書かない（S-11-001-014・例外の握りつぶし禁止）
- [ ] 一覧の取得では、ループの中で SQL を発行しない（S-11-001-016・N+1・ループ内SQLの禁止）
- [ ] 1万件を超える可能性がある取得は、全件をメモリに載せずに順に処理する（S-11-001-017・大量データの扱い）
- [ ] domain は application・infrastructure に依存しない（S-11-001-018・レイヤーと依存方向）
- [ ] 業務領域（tour・reservation・transfer）ごとにパッケージを分ける（S-11-001-019・パッケージ構成）
- [ ] クラス名・項目名は業務用語集の英名に合わせる（予約 Reservation、振込状況 TransferStatus）（S-11-001-020・命名規則）
- [ ] 許可リストにない依存ライブラリは追加しない（S-11-001-021・使用するライブラリと版）
- [ ] java.util.Date と System.exit は使わない（S-11-001-022・禁止API）
- [ ] 手配 API の URL とタイムアウト値は設定ファイルに置く（S-11-001-024・設定値の外出し）
- [ ] フォーマッタの設定ファイルに従う（S-11-001-026・コードの書式）
- [ ] 旧システムから持ち込むコードの既存違反はベースラインに記録し、新しいコードでは禁止する（S-11-001-027・既存の悪い書き方）

## テストを書く（業務承認の要らない振る舞い）

- [ ] 定義にない区分値を受け取ったら業務エラーにし、処理を進めない（S-11-001-015・想定外入力への防御）

## 動かして測り、PR に結果を添える

- [ ] 画面処理のトランザクションは1秒以内に終える（S-11-001-011・長時間トランザクションの禁止）
